# Master Website-Prompt Template

Fill every `{{PLACEHOLDER}}` with real, business-specific content and **real written
copy** (headlines, About paragraph, card lines, tagline). Keep the wording, order,
and — for the trust tier — the verification framing. Adapt the service/menu sections
and the whole mood to the chosen playbook (`vertical-playbooks.md`). Write the copy at
the "specific and human" level (`human-copy.md`), never generic. Delete sections that
don't fit an industry and say why in one line. Depth is the goal — match the worked
examples, not a skeleton.

Output the intro paragraph first (see SKILL.md Step 4), then everything below.

Legend: **[CORE]** = always include · **[PREMIUM]** = experience-tier (barber/salon/
restaurant/detailing/boutique/luxury e-comm) · **[TRUST]** = service-tier (home/trade/
auto-repair/pet-care) · **[ECOMM]** / **[MULTI]** = only when applicable.

**[CORE] BUSINESS INFO**
Name / phone / email / address / hours (label conflicting hours across sources and say "verify") / owner or rep (only if approved) / years in business / neighborhood or landmark / payment methods / license or entity number (TRUST/auto: internal verification only). Present ratings + review counts **per platform** as "shown in the listing" working data to re-verify on launch day. **Any hard fact you did NOT verify from a source is written as a loud marker — `>>> UNVERIFIED — CONFIRM <<<` — never a soft or plausible-looking value.**

**[CORE] >>> DO NOT PUBLISH UNTIL VERIFIED <<<**
Immediately after the business info — near the TOP of the prompt, not buried at the bottom — put a prominent block listing every hard fact you could NOT verify (prices, hours, rating/review counts, phone, address, license/entity, and any "free estimate"/financing/warranty claim). Tell the builder plainly: do not publish any value in this list until the owner confirms it; a wrong price/number on a live site is worse than a missing one. This block is the fail-safe against a placeholder getting skimmed past inside a long brief and shipped live — which is why it sits up top, in addition to any [TRUST] checklist at the bottom.

**[PREMIUM] VISUAL STYLE**
Describe the look concretely: background (e.g. near-black/charcoal or warm dark), accent colors, typography feel, hero treatment, spacing, texture, hover/glow behavior, and the overall mood in adjectives. State what to AVOID (generic template look, cheap overdesign, fake stock imagery). For restaurants/e-comm that already have an AI-looking site or a reference image, say so and describe how to beat/match it.

**[CORE] DESIGN DIRECTION + COLOR PALETTE**
Give a concrete palette: 6-9 named swatches with hex + usage notes (accent for buttons/prices; dark for trust/structure; light for backgrounds). Tell the builder to pull the real logo's colors if a logo exists.

**[CORE] TYPOGRAPHY**
Heading style + body style + button/label guidance; 3-5 named font suggestions fitting the brand (e.g. Playfair/Cinzel for luxury; Barlow/Oswald for rugged; Inter/Manrope/Montserrat general). Avoid fonts that fight the brand.

**[CORE] ANIMATIONS**
Specific, on-brand animation list: custom loading screen; logo/text reveal; scroll fade-ins; card hovers; sticky nav (glass/blur); sticky mobile action bar; plus a signature motif from the playbook (blade swipe, sauce drip, gold globe, water sweep, road line). Keep it lightweight and fast; not cheesy.

**[CORE] CUSTOM LOADING SCREEN**
Text: "{{business name}}" · Subtext: "{{real tagline • of • services}}" · Animation idea: {{on-brand reveal, then a clean fade into the homepage}}.

**[CORE] WEBSITE STRUCTURE**
Write each section with real copy, not directions-only. Adapt names/order to the playbook.

1. **HEADER / NAVIGATION** — logo + nav links (tuned to sections); header CTAs (primary + Call); sticky nav; mobile sticky bottom action bar. Phone {{phone}}.
2. **HERO** — 2-3 real headline options (specific, human); a real subheadline naming the services/items + area; primary + secondary CTA; trust/spec badges (real rating, signature facts); hero image = a real photo, labeled placeholder if none.
3. **[PREMIUM] QUICK STRIP under hero** — a fast row of favorites / signature items / featured vehicles / top services with direct action buttons.
4. **ABOUT** — a real, written paragraph (2-5 sentences) in the brand's voice, using real specifics (neighborhood, years, what they're known for). Owner named only if approved. No filler mission block.
5. **SERVICES / MENU / PRODUCTS / INVENTORY (primary section)** — cards with **real names, real one-line descriptions written in-voice, and real prices** where verified; each card an action button (Book/Order/Ask/Request/View). Pull the real menu/service list from the source; use labeled placeholders where the item exists but details are unknown. **Never emit an unverified price — write `>>> PRICE UNVERIFIED — CONFIRM <<<` instead of guessing one**, and add it to the DO-NOT-PUBLISH block up top.
6-11. **PLAYBOOK-SPECIFIC SECTIONS** — the signature sections for the vertical (e.g. barber: Gallery + Why-Choose-Us + Instagram + Booking band; restaurant: Sauces/Specialties + Combos; home/trade: one section per trade + before/after; auto sales: vehicle-detail + financing + trade-in + service; e-comm: catalog + product detail). Each with real copy and a CTA.
12. **GALLERY** — real photos from IG/site/listings; filters where useful; labeled placeholders + code comments if blocked; no unrelated stock passed off as real.
13. **[TRUST] BEFORE-AND-AFTER** — sliders per service; before/after/category/area/summary; no customer addresses. (Skip for verticals where it doesn't fit.)
14. **HOW IT WORKS / BOOKING or ORDER FLOW** — 3-4 real steps; no instant-approval/instant-estimate promises unless confirmed.
15. **REVIEWS** — per-platform ratings as working data (verify launch day); real review themes/quotes source-labeled; editable `[Add verified <platform> review]` placeholders; never invent.
16. **SERVICE AREA / LOCATION** — cities/region or the single location; map; directions; "Check Availability" + ZIP for service businesses.
17. **BOOKING / ORDER / ESTIMATE / CONTACT FORM** — fields tuned to the goal (appointment, order, estimate, inquiry, pre-qualify, trade-in); consent; success state; photo upload where useful.
18. **HOURS / AVAILABILITY** — display verified hours; reconcile conflicts; editable per-day fields.
19. **CONTACT / LOCATION DETAIL** — name, address, phone/email, all links, click-to-call, text (if confirmed), map + directions, socials; privacy note if the address is residential.
20. **FAQ** — 8-14 real questions for the vertical; unverified answers → "Call {{business}} to confirm."
21. **FINAL CTA** — headline options + subheadline recapping the real offer + buttons; phone.
22. **FOOTER** — name, tagline, address, phone/email, links (profiles + booking/order + legal), footer tagline options.

**[ECOMM] STORE BUILD** (add when selling online)
Product catalog, product detail pages, cart, checkout, order confirmation, order-tracking page with a tracking-number field, optional account flow, and an editable product data structure so the client can add/edit products later. Payment integration as connect-your-own-credentials (Stripe/etc.); never hardcode secrets; mark where the backend connects.

**[MULTI] MULTI-LOCATION ARCHITECTURE** (add for subdomains)
One parent brand site + one sub-site per location under subdomains; shared components; a per-location data file (address, hours, phone, reviews, map, menu/inventory, photos, schema). List each location's own Google/Yelp/Facebook links.

**[CORE] TECHNICAL REQUIREMENTS**
Responsive modern site (React, Next.js, or clean HTML/CSS/JS); reusable components; mobile-first; semantic HTML; fast image loading; accessible form labels; clickable phone/email; mobile sticky action bar; SEO metadata; the right business schema. Editable data + components: /data/{{services|menu|vehicles|products}}, /data/reviews, /data/siteContent; /components/{{Card, Grid/Gallery, ReviewCard, Form, Header, Footer, + vertical components}}. Make the primary data file dead-simple for the client to update.

**[CORE] FORM FUNCTIONALITY**
Validate required fields; success message; integration-ready for email/Formspree/Resend/Supabase; optional photo uploads; spam protection; no exposed credentials. If no backend, build the interface and mark where the production service connects.

**[CORE] LOCAL SEO**
Real keywords, no stuffing: "{{Business}}" + "{{service/item}} {{city}} {{state}}" for each core offering + nearby-city variants.

**[CORE] SCHEMA MARKUP**
JSON-LD for the correct type ({{LocalBusiness / HomeAndConstructionBusiness / Handyman / PetGroomer / Restaurant / AutoDealer / Store}}), PostalAddress, Telephone, {{Email}}, OpeningHoursSpecification (after hours verified), AggregateRating (only when current and verified — else omit), menu/product/vehicle entries only from real data, service area, SameAs links, Review data only when genuine. No fabricated ratings/reviews.

**[CORE] PHOTO / SCRAPING INSTRUCTIONS**
List each source link. Retrieve logo, real service/food/product/vehicle photos, interior/team/owner photos (if approved), before-and-after, review excerpts. Verify a provided Instagram matches the business/location before pulling its photos. Public images only; no login walls or private content. Where blocked, insert placeholders + code comments marking where each real image belongs.

**[CORE] COPY & VOICE RULES (anti-generic — keep this block in every prompt)**
Write all site copy in {{this business's real voice: e.g. gritty & craveable / premium & authoritative / warm & friendly / no-nonsense local}}. Use the real, specific details above (real service/menu names, prices, neighborhood, years, the brand's own phrases). This site must NOT read like a generic AI/template website. Do not write: "Welcome to…", "Here at…", "nestled in the heart of", "whether you're looking for… look no further", "we pride ourselves on", "dedicated to providing", "top-notch", "state-of-the-art", "one-stop shop", "elevate your…", "in today's fast-paced world", empty mission/values blocks, or fabricated stats/badges. Favor concrete lines with a point of view, varied sentence rhythm, and real local detail over stacked adjectives. Keep exclamation points and em-dashes rare.

**[TRUST] VERIFICATION CHECKLIST + DO-NOT-INVENT + LICENSED-TRADE DISCLAIMER**
Include the full blocks from `example-worked.md` for service/trade/auto-sales businesses: a thorough "verify before publishing" checklist; an explicit "Do not invent" list (licenses, insurance, warranties, reviews, ratings, free estimates, guaranteed approvals, years, emergency/24-7); and a licensed-trade or industry-legal disclaimer with careful scope wording.
